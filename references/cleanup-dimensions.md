# 清理维度对照（学自 Czkawka / rmlint / dupeGuru / fclones）

> `file-duplicate-cleanup` skill 的参考资料：主流开源清理工具覆盖哪些维度、本工具做到哪一步、哪些故意不做。

## 维度对照表

| 维度 | 说明 | 本 skill |
|---|---|---|
| 重复文件 | 名/大小/哈希 | ✅ 已有（四层法更强，含相似度） |
| 重复文件夹 | 整目录当一个整体比对 | ✅ 已有（模式三，学自 dupeGuru `FOLDERS`） |
| 空文件 | 0 字节 | ✅ 已有 |
| 空文件夹 | 无子项目录树 | ✅ 已有 |
| 大文件 | 列出占空间大户 | ✅ 已有（`scan-big`，仅列不删） |
| 临时文件 | 编辑器锁文件/下载未完成/临时备份/系统垃圾/pyc/日志 | ✅ 已有（`scan-temp`，`--min-age-days` 年龄过滤 + `--cats` 分类） |
| 构建产物 | `node_modules`/`build`/`.gradle`/`__pycache__` 等 | ✅ 已有（`scan-build`，按「可重建 / ⚠发布成品」两级分） |
| 重复音乐 | 按音频标签/指纹匹配 | ⬜ 不做（依赖 mutagen/ffmpeg，场景窄；内容哈希已能覆盖"同一文件的两份拷贝"） |
| 相似图片/视频 | 感知哈希查"看着像"的媒体 | ⬜ 不做（需 PIL/imagehash/ffmpeg；**相似≠重复，易误删**，风险不划算） |
| 坏扩展名 / 损坏文件 | 扩展名与真实类型不符、不可读 | ⬜ 暂不做（需读文件头/试打开，误报多） |
| 硬链接/符号链接重复 | 同一 inode 的多个入口 | ⬜ 不做（Windows 少用；`scan-dupes` 已按 inode 去重，不会把硬链接误报成重复） |

## 借来的巧思

- **dupeGuru `FOLDERS` 模式**：把一个文件夹当整体比对，找出"整目录是另一目录的副本"→ 本工具的模式三。
- **fclones 哈希流水线**：大小分组 → inode 去重 → 前缀哈希（64KB）→ 全量哈希，避免对每个文件都做全量哈希 → `scan-dupes`。
- **Czkawka `delete-method`**：怎么选保留哪份（first/newest/oldest/shortest）→ `clean --keep`。
- **Czkawka JSON 输出**：脚本化、可接后续处理 → 本工具所有 scan 都出 JSON，`scan-build --emit-paths` 直接衔接 `clean-paths`。
- **Czkawka scan cache**：缓存扫描结果给全盘体检提速 → **未做**（本环境全盘扫描的瓶颈是机械盘 IO，且用户会话自清会让缓存失效）。

## 未采纳的理由（原则）

**"相似 / 看着像"类维度一律不自动删。** 相似 ≠ 重复：两张相似的图可能是不同角度、不同版本；一段相似的音乐可能是不同编曲。误删成本远高于省下的空间。这类只做"列出来给人看"，不做自动处置——而本工具目前的定位是"能安全自动处置"，所以干脆不做。
