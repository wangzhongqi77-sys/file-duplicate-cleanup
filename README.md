# fclean — 文件清理工具箱

零依赖、只扫不动、删除必进回收站的命令行文件清理工具。用来回答一个很烦的问题：**这堆文件里，哪些是可以放心删的？**

```bash
python fclean.py scan-build --root D:/Projects --emit-paths safe.txt
python fclean.py clean-paths --list safe.txt --apply --trash-dir D:/__回收站__
```

---

## 它解决什么问题

清理工具很多，但直接扫「重复文件」往往答不准。以下是本工具在真实目录上跑出来的结果：

| 场景 | 「重复文件」扫描的结论 | 真实情况 |
|---|---|---|
| 一个 Hexo/Hugo 项目目录 | 5172 组重复，"可省 1589 MB" | 排除 `source↔public` **构建镜像**后，真正可省的只有 **1.69 MB** |
| 一个 8 项目的仓库堆（1855 文件） | 62 组重复 | 54 组是构建镜像，其余是第三方字体和 LICENSE —— **没有可安全删的重复** |
| 同一仓库堆换个角度扫构建产物 | 重复扫描在这里**零收获** | 22 个构建目录占 **2.41 GB**，其中 **2.34 GB 可安全重建** |

**结论：真正的空间大户通常不是"重复文件"，而是构建产物；而有价值的"重复"大多是不能删的构建镜像。** 本工具把这两件事分开处理。

## 为什么选它（以及什么时候别用）

同类成熟工具很多：**fclones**（Rust，最快的去重器）、**Czkawka**（功能最全）、**npkill**（专清 `node_modules` / `.next`）。本工具**不跟它们拼速度**，它的定位是 Windows 中文环境下的「**安全 + 可控 + 零门槛**」：

| 你在意的事 | 本工具 | 同类工具 |
|---|---|---|
| 删错了还能捞回来 | ✅ 三级兜底进回收站，失败自动还原原位 | ❌ npkill 官方明示无回收站（误删需文件恢复工具）；fclones / rmlint 多为直接删除 |
| 别把「源码↔产物」误报成重复 | ✅ 构建镜像识别，虚报单独排除 | ❌ 多数按哈希直报，容易虚报"可省 X GB" |
| 别把 `public` / `dist` 当垃圾删了 | ✅ 发布成品分级，默认不碰 | ⚠️ 多数只提示"敏感目录"，不区分发布成品 |
| 不想装 node / npm / Rust 工具链 | ✅ 单文件 Python，零第三方依赖 | ❌ 需要 `npx`、装包或下载二进制 |
| Windows 中文路径 / 隐藏目录 / junction | ✅ 实测适配，踩坑都记在 `references/` | ⚠️ Linux 优先的工具在这里容易翻车 |

**什么时候别用它**：几十万文件以上的全盘去重，或 Linux / macOS 生产环境 —— 请直接用 [fclones](https://github.com/pkolaczk/fclones) 或 `jdupes`，它们快一到两个数量级。本工具是为「**想安全地把确定的东西删掉**」这个场景做的。

## 安装

无第三方依赖，Python 3.8+ 即可：

```bash
python fclean.py --version
```

可选：装 `Send2Trash` 可让回收站通道更稳（不装则回退到 Windows 原生 `ctypes` 调用）。

```bash
pip install Send2Trash
```

## 六个扫描模式 + 两个删除入口

**扫描（永远只读）**

| 命令 | 查什么 |
|---|---|
| `scan-dupes` | 重复文件（大小分组 → inode 去重 → 前缀哈希 → 全量哈希） |
| `scan-dirdupes` | 重复文件夹（整目录指纹比对 + 目录对聚合） |
| `scan-empty` | 0 字节空文件 + 空文件夹 |
| `scan-similar` | 文本相似度（查"版本冗余""双格式重复"） |
| `scan-big` | 大文件清单（占空间大户） |
| `scan-temp` | 临时垃圾（编辑器锁文件/下载未完成/临时备份/系统垃圾/pyc/日志） |
| `scan-build` | **构建产物**（`node_modules`/`build`/`.gradle`/`__pycache__`…），按「可重建 / ⚠发布成品」两级分 |

**删除（默认预演，加 `--apply` 才动手）**

| 命令 | 用途 |
|---|---|
| `clean --report <json>` | 按扫描报告删（重复组保留 1 份，`--keep first/newest/oldest/shortest`） |
| `clean-paths --list <txt>` | 按路径清单删整目录/文件（自动去重、`--exclude` 排除） |

---

## 设计原则

1. **默认预演**：所有删除命令不加 `--apply` 只打印计划，不动任何文件。
2. **删除一定可还原**：优先移入系统回收站；给了 `--trash-dir` 则移进同盘回收目录（**秒完成**）。三条通道逐级兜底，全部失败会**自动把文件还原回原位**。
3. **两级安全分类**：构建产物区分 `safe`（可重建）与 `output`（⚠ 发布成品，如网站 `public`/`dist`）。**默认只删 safe，动成品必须显式加 `--include-output`**。
4. **构建镜像不误删**：自动识别 `source/static/themes ↔ public/dist/_site` 这类「源码↔产物」镜像，单列并默认跳过。
5. **失败即停**：批量删除每批 10 个，出现失败立即停止后续。

## 性能实测

| 操作 | 实测 |
|---|---|
| 扫描 14652 个文件（跳 AppData） | 4.5 秒 |
| 扫描 24172 个文件的目录树 | 1.8 秒（构建产物模式） |
| 移动 2000 文件目录 → 同盘回收目录 | **0.002 秒** |
| 移动 2000 文件目录 → 系统回收站 | 114.6 秒（≈57ms/文件，Windows 逐个入 `$Recycle.Bin`） |

> **删整目录或批量文件时优先用 `--trash-dir`**（同盘改名，等价于瞬间完成），比系统回收站快 5 个数量级。

### 进阶能力（三个可选开关，默认都不开）

| 开关 | 作用 | 什么时候值得开 |
|---|---|---|
| `--tail-size N`（默认 4096，`0`=关闭） | 全量读之前先看一眼文件**末尾**，结尾不同就当场淘汰 | 几乎总是有益、成本极低；查日志 / 素材类文件尤其值 |
| `--cache <db>` | 把哈希存进 SQLite，第二次扫同一批文件时直接复用 | **大文件 / 慢盘才划算**：实测 2×200MB 相同文件 `0.70s → 0.00s`；但**小目录反而略慢**（查库开销 > 重算哈希） |
| `clean --link hard` | 重复副本改成**硬链接**：路径都还在、磁盘只占一份 | 想省空间但不敢删文件时。**注意硬链接不是备份**，改一个另一个也变；跨驱动器会自动跳过、原文件不动 |

> **为什么缓存不是越快越好**：它省的是「读文件内容」的时间。小文件在 SSD 上重算哈希本来只要几毫秒，
> 反而不如查一次数据库划算。**文件越大、磁盘越慢，它才越值。**
>
> 另外：`clean --link hard` 在跨驱动器时会失败（Windows `WinError 17`），工具会检测出来并跳过，不会丢文件。

## 能力边界

**做**：重复文件、重复文件夹、空文件、空文件夹、大文件、临时垃圾、构建产物。

**不做**（有意为之）：
- **相似图片/视频**（感知哈希）—— "相似 ≠ 重复"，误删风险大于收益
- **重复音乐**（音频标签/指纹）—— 依赖外部库，场景窄
- **坏扩展名/损坏文件** —— 误报多

---

## 已知局限

- 全盘体检在机械盘上较慢（受 IO 限制）：建议**分段扫描**并跳过 `AppData`。
- 构建产物名表是启发式的：自定义输出目录（在 `fclean.py` 的 `ARTIFACT_*` 常量里）可能需要按项目补。
- 系统回收站在文件数多的目录上很慢 —— 这是 Windows 的行为，不是工具的性能问题。
